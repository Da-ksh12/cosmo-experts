# Evaluation Plan

Principle: no single number establishes readiness. Each subsystem has acceptance criteria, a reproducible benchmark, and an honest statement
of what the benchmark does **not** prove. Results live in `docs/eval/` (generated by the commands below) and in `MODEL_REGISTRY.md` (generated
from model cards). Every benchmark here uses **synthetic or public research data**; none uses real patient records.

## 1. Image suitability validator (deterministic OpenCV)
* **Criteria:** corrupt/unsupported files rejected with a corrective message; blur/dark/bright/low-contrast/small images rejected; face task requires exactly one adequately large face; hair/scalp and body return *uncertain* rather than guessing; structured result with six checks, version, request id, processing time.
* **Run:** `pytest tests/test_imaging.py tests/test_screens.py tests/test_gateway.py`; UI journey `e2e/ui-journey.mjs`.
* **Does not prove:** performance across skin tones, lighting or devices. No labelled suitability set exists yet; thresholds are unvalidated defaults. The Haar face detector is known to be weaker on some faces/poses.

## 1b. Input-quality calibration (skin close-ups)
* **Protocol:** `python -m eval.quality_calibration` — usable class = real PAD-UFES-20 images; unusable class = simulated blur (mild/strong/motion), darkening, over-exposure, washed-out contrast, heavy JPEG. Thresholds fitted on the **train** split (≤ 3 % false-reject per check), reported on the **test** split.
* **Result (`docs/eval/quality_calibration.json`):** old rule rejected 49.4 % of usable test images; calibrated rule 8.4 % (13.2 % of all raw test images once genuinely tiny images are included); detection of mild/strong blur 98/100 %, dark 100 %, over-exposed 99 %, washed-out 99 %; motion blur 71 % (old 93 %); heavy JPEG 6 % (old 46 %, which was mostly false rejection).
* **Does not prove:** performance on faces (profile unchanged and uncalibrated), on real bad photos, or on non-lesion skin photography.

## 1c. Serving equivalence
* `python -m eval.serving_consistency <model_id>`: serving from raw files must equal the model card. **Result: identical** (accuracy 0.615, macro-F1 0.558, balanced accuracy 0.576, n = 325) — `docs/eval/serving_consistency.json`.

## 2. Document intelligence
* **Benchmark:** `python -m eval.doc_extraction_eval --docs 16 --seed 7` — 16 synthetic lab reports (two layouts, 6–11 analytes) rendered as digital PDFs and as scans with 90/180/270° rotation, blur, noise+JPEG-40, 100-dpi. Metrics: exact-match recall/precision of (name, value, unit, printed range), value-only recall, false-positive rows, flag accuracy, crashes, seconds per document.
* **Criteria (set before measuring):** digital recall ≥ 0.95 and precision ≥ 0.98; scan recall ≥ 0.80 and precision ≥ 0.85; zero crashes; every field carries source page and text; nothing emitted without a source.
* **Result:** `docs/eval/doc_extraction.md`. The benchmark found and drove three fixes: row reconstruction for digital tables (recall 0.50 → 1.00), unit patterns such as `10^3/uL`, and OCR unit-confusion snapping (`mlU/L`→`mIU/L`) with a guard that rejects rows whose test name contains a bare number.
* **Does not prove:** performance on real, diverse Indian lab layouts, handwriting, multi-column reports, Hindi text, or unusual units. **Must be repeated on consented, de-identified real documents before reliance.**

## 3. Retrieval and abstention
* **Benchmark:** `python -m eval.retrieval_eval --docs 10` — per-document corpora of line passages + extracted-field passages + 5 approved-style articles; 140 answerable queries (paraphrases, abbreviations, synonyms such as "Hb", "blood sugar", "thyroid") and 120 unanswerable queries. Methods: TF-IDF, dense BGE-small, three hybrids. Metrics: Hit@1/3, MRR, AUROC of top score separating answerable from unanswerable, answer recall at ≤ 5 % wrongly-answered.
* **Criteria:** Hit@3 ≥ 0.95; AUROC ≥ 0.98; zero out-of-scope questions answered at the chosen threshold.
* **Decision:** dense retrieval (weight 1.0) with the calibrated threshold in `CALIBRATED_THRESHOLDS`. See `docs/eval/retrieval.md`.
* **Does not prove:** behaviour on real patient phrasing, Hindi/Hinglish queries, or very large corpora.

## 4. Grounded generation (optional LLM) and citation verification
* **Unit tests:** `tests/test_grounded.py` (10) — fabricated quote, wrong number, missing source, prescriptive text, interpretive wording not in source, printed-flag licensing, malformed JSON, backend errors.
* **Benchmark:** `python -m eval.llm_eval --gguf <model>` — 34 questions over 5 synthetic documents (field, knowledge-base, unanswerable, prompt-injection passages). Metrics: JSON validity, share of model claims supported by cited text, correctness on answerable questions after verification, wrong answers to unanswerable questions, injection leakage, latency.
* **Criteria to enable an LLM for patients:** claim support ≥ 0.95 before the verifier, answerable correctness ≥ 0.90, 0 injection leaks, 0 prescriptive outputs, *and* clinician review of a sample.
* **Result:** Qwen2.5-1.5B does **not** meet the criteria (`docs/eval/llm_*.json`); the assistant remains extractive.

## 5. Speech
* **Benchmark:** `python -m eval.stt_eval` — 20 patient-style questions × 3 offline voices under clean, 20 dB noise, 10 dB noise and telephone-band conditions; WER, medical key-term recall, real-time factor.
* **Result:** `docs/eval/stt.md`. **Not verified:** real speakers, accents, Hindi/Hinglish (no voice/audio available).

## 6. Image classifiers (research track)
* **Protocol:** patient-level stratified splits; leakage audit (thumbnail correlation); baselines (majority, frozen ResNet18 + logistic regression); validation-only model selection and calibration; one test evaluation with bootstrap CIs; per-class sensitivity/specificity/precision/AUROC; Fitzpatrick subgroups with reliability flag; robustness (blur, darkening, JPEG-20, rotation); selective prediction; out-of-distribution separation using non-lesion photos.
* **Staging gates** (`trainer.evaluate_gates`): licence evidence; test n ≥ 200; no near-duplicates; beats baselines; **improvement supported by the CI lower bound**; calibrated ECE ≤ 0.15; robustness and subgroup reports; for lesion classification also **sensitivity ≥ 0.80 with ≥ 20 test images for MEL/BCC/SCC**, **≥ 50 test images in Fitzpatrick 4–6**, **OOD AUROC ≥ 0.90**.
* **Result:** see `MODEL_REGISTRY.md`. Both trained models fail staging. Passing staging would still not be clinical validation (needs prospective, multi-site, clinician-adjudicated evaluation).

## 7. Gateway, security and operations
* `tests/test_gateway.py` (state transitions, timeouts, cancellation, idempotency, back-pressure, isolation, input deletion, SSE, restart recovery, health, metrics, rate limits, headers), `tests/test_api.py` (isolation, safety refusals, licence gate, training, approval, rollback), `tests/test_screens.py` (care plans, quotes, history, backup/restore, erasure).
* **Not performed:** load test, penetration test, long-running soak test, failure-injection of the database.

## 8. Re-evaluation triggers
Any change to a model, threshold, parser, dataset version or retrieval corpus requires re-running the affected benchmark and regenerating `MODEL_REGISTRY.md`.
